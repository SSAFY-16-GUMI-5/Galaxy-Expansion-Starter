# AI와 함께 학습하며 구현하기

이 스터디는 AI 사용을 금지하지 않습니다. 대신 생성된 코드의 **설계 의도, 생명주기, 재사용을 검증한 방법**을 참가자가 설명할 수 있어야 합니다.

## Step 1 — 설계 질문

```text
내 개발 언어는 [언어]입니다. AGENTS.md와 ASSIGNMENT.md를 읽고,
객체 풀의 소유권·자료구조·용량 정책을 비교해 주십시오.
추천 설계 1안, 대안 1안, 예상되는 실수 3가지를 설명하고
아직 완성된 Acquire/Release 구현은 작성하지 마십시오.
```

## Step 2 — 스타터 뼈대

```text
선택한 설계에 맞춰 solution/에 프로젝트를 생성하십시오.
CosmicObject, ObjectPool 인터페이스, JSONL Adapter, 실행 엔트리포인트,
빌드/실행 명령과 단위 테스트 틀을 작성하되 Object Pool 핵심 알고리즘은 TODO로 남기십시오.
공통 계약과 검증기 파일은 변경하지 마십시오.
```

## Step 3 — 직접 구현 후 리뷰

```text
내가 구현한 ObjectPool을 코드 리뷰해 주십시오.
객체 동일성·이중 반환·초기화 누락·수명 문제를 중점 검사하고,
실패를 재현하는 테스트를 먼저 제안하십시오.
변경 이유를 설명하고 나의 동의 없이 핵심 로직을 통째로 교체하지 마십시오.
```

## Step 4 — 검증 및 발표

```text
사용 중인 언어의 테스트와 JSONL 검증기를 실행할 수 있도록 도와주십시오.
실행한 명령, 실제 테스트 결과, 미검증 항목을 분리해 보고하고
발표용으로 자료구조 선정 이유, 오류 사례, 트레이드오프를 간단히 정리하십시오.
```

## 체크 사항

- AI가 작성한 코드는 이해하고 수정할 수 있는 범위에서 사용합니다.
- 생성된 코드가 맞다는 말 대신 단위 테스트와 로그로 확인합니다.
- AI가 `docs/PROTOCOL.md` 또는 검증기를 고치자고 제안하면 먼저 규격 위반인지 확인합니다.
- 도구가 환경 명령을 실행하지 못하면 성공했다고 보고하지 않습니다.
- GitHub Actions에 언어별 빌드/테스트 job을 추가합니다. 공통 CI만 통과했다고 언어별 솔루션이 정상 실행된 것은 아닙니다.
